# VITALINK clinical workspace

A facility-scoped maternal referral workspace built with Next.js 16.4.2, React 19.3.0 and strict TypeScript 5.9.3. The interface uses warm-white surfaces, navy typography and restrained semantic color. Every dashboard count comes from the authenticated API. Demonstrations use synthetic identifiers only.

## Run

Use Node 22.18+ (verified installed: 24.12.0). Start PostgreSQL and `services/api` first, then:

```powershell
cd apps/web
npm ci
$env:API_BASE_URL = 'http://127.0.0.1:8087/api/v1'
$env:APP_ORIGIN = 'http://localhost:3017'
npm run dev
```

Open the exact `APP_ORIGIN`. Sign in using an account generated by the API's local fixture script; no credentials are embedded in the UI. Local development can use an ephemeral process session key, which signs users out after a server restart.

For production builds and local production-mode demonstrations:

```powershell
npm run build
# Set SESSION_SECRET to a freshly generated canonical base64 32-byte key.
# The root environment generator creates one without printing it.
$env:COOKIE_SECURE = 'false' # Explicit localhost HTTP demo only.
npm start
```

`SESSION_SECRET` is mandatory when a production server handles authentication requests. Missing/invalid configuration prevents a usable login. Production cookies default to Secure. An explicit insecure-cookie override is accepted only for a localhost application origin. HTTPS and Secure cookies are required for a nonlocal deployment; no public deployment is part of this release.

## Available tooling

- `npm run typecheck`: strict TypeScript checking, with unchecked indexed access enabled.
- `npm test`: Node's in-process test runner verifies response contracts, clinical priority floors, proxy allowlists, CSRF origin checks and session configuration.
- `npm run build`: actual Next production compilation, type checks and prerendering; no type-check suppression.
- `npm run test:e2e`: six Playwright real-service browser scenarios, including axe-core WCAG checks and actual screenshots. Requires the running API, dashboard and generated local credentials.
- `node scripts/dev-server.mjs`: a standard custom Next development server when the CLI supervisor cannot create a subprocess. It serves this application's real routes.

The host currently denies network package downloads through its configured proxy. `scripts/use-local-packages.mjs <absolute-node_modules>` can recover the exact installed open-source dependencies from an existing local package installation. It copies packages only, never another application's source. Package versions/provenance are recorded in `evidence/offline-package-provenance.json`; the lock includes resolved URLs, integrity hashes and platform-specific packages for a normal `npm ci` elsewhere.

## Workflow and safety

The workspace provides secure sign-in, scoped operational metrics, referral inbox, urgent queue, clinical snapshot, deterministic rule explanation, stored measurement timeline, status history, explicit acknowledgment and closure. Acknowledgment requires a confirmation and a validated server response. Server receipt alone never becomes clinical acknowledgment. Browser disconnection disables clinical actions and marks loaded information potentially stale. Unsent Android referrals cannot be counted by the server and are described explicitly as unavailable to this dashboard.

Missing measurements display as missing. Severe BP or symptoms cannot be displayed with a low-priority badge: contradictory API responses are rejected. A no-trigger result is never called healthy. No validated predictive model is available; the AI status explains rules-only operation without decorative confidence values or invented explanations.

## Security boundary

Browser requests use same-origin backend-for-frontend routes. AES-256-GCM encrypted, authenticated, HttpOnly/SameSite=Strict cookies hold the opaque backend session. Tokens never enter client JavaScript, localStorage or API session responses. Tokens expire within eight hours and logout revokes the backend session when reachable. All clinical/auth responses are no-store. Mutations reject absent/foreign Origins using `APP_ORIGIN`; reverse proxies must set that origin to the externally visible URL. The proxy has an explicit endpoint/method allowlist and never accepts an upstream host from the browser. The API remains responsible for role and facility authorization on every object access.

Content Security Policy blocks framing, remote connections and embedded objects. Next hydration currently requires inline scripts/styles, so CSP retains `unsafe-inline`; nonce-based CSP is a documented hardening opportunity. Error messages never echo upstream payloads or credentials. Docker image runs as the unprivileged `node` user. Docker execution remains dependent on host engine access.

## Evidence

Use only completed command results in `evidence/`. The presence of E2E source is not proof of browser execution. `playwright-attempt.txt` records an environmental `spawn EPERM` before the test runner could execute its scenarios. The release audit must distinguish that attempt from any later direct-CDP browser checks. Tests and screenshots use synthetic records stored by the real backend; no frontend fixture store supplies clinical counts.
