# VITALINK referral API

Java 21, Spring Boot 3.5.16, Spring Security, JDBC/PostgreSQL, Flyway and Bean Validation. Synthetic data only; deterministic research rules are not medical-device validation. Shared request/response fields are in `../../contracts/API_CONTRACT.md`. The executable OpenAPI 3.0.3 specification is served at `/api/v1/openapi.yaml` and generated by `python scripts/generate-openapi.py`.

## Local Windows development

From repository root:

```powershell
services/api/scripts/start-database.ps1
. services/api/scripts/environment.ps1
services/api/scripts/maven.ps1 -o -f services/api/pom.xml package
services/api/scripts/run-local.ps1
```

The Maven launcher discovers installed Maven; set `JAVA_HOME` to JDK 21. On this audited workstation the environment script uses the verified Microsoft JDK 21.0.10. `-o` uses cached artifacts; on a network-enabled developer machine omit it to resolve pinned dependencies. `scripts/test-local.ps1` runs tests against the project database. `scripts/start-api.ps1` starts a hidden project process; stdout/stderr and its PID are written under ignored `.runtime/`. `scripts/stop-database.ps1` stops only this cluster.

PostgreSQL 18 binaries default to `C:/Program Files/PostgreSQL/18/bin`; pass `-PostgresBin` to select another installation. Data live in `.runtime/postgres`, listening only on `127.0.0.1:55432`. The normal PostgreSQL executable is used if the pg_ctl Windows helper cannot create its restricted child process; no privileges or security settings are changed.

`scripts/generate-dev-config.py` creates random local database credentials and synthetic worker, doctor, administrator and out-of-scope accounts. Find them in `.runtime/demo-credentials.json`; do not copy them into committed source, logs or screenshots. Runtime passwords are BCrypt-hashed into the database. Existing user hashes are never silently replaced during bootstrap.

## Configuration and networking

Required environment variables: `DATABASE_URL` (JDBC PostgreSQL URL), `DATABASE_USER`, `DATABASE_PASSWORD`. Optional `VITALINK_BOOTSTRAP_USERS` is a JSON array of explicit `{username,password,role,facilityId}` account fixtures (password 16–72 ASCII characters); absent means no default accounts. Use a proper provisioning process for any future non-demo system.

`API_BIND_ADDRESS` defaults to `127.0.0.1`. Local helper scripts set `API_PORT=8087` unless explicitly configured, because host port 8080 is already used on this workstation; the container's internal default remains `8080`. Set binding `0.0.0.0` inside a container. External use requires TLS and a reviewed reverse-proxy configuration. Android emulator uses host alias `10.0.2.2:8087`; physical devices need a reviewed LAN setup or `adb reverse tcp:8087 tcp:8087`, never public exposure. The web server proxies API requests; backend CORS is disabled and does not permit browser cross-origin credential use.

## Safety and reliability

- Severe systolic **OR** diastolic pressure and each concerning symptom cause URGENT findings. Missing values cause review; NO_TRIGGER means only no listed trigger, never assurance of health.
- Snapshots are immutable. PostgreSQL triggers reject UPDATE. A stable referral UUID, idempotency header, request fingerprint, transactional advisory locks and unique constraints prevent concurrent duplicate ingestion.
- A receipt is SERVER_RECEIVED. Only an authorized doctor/admin at that facility may acknowledge. Closure requires acknowledgment. Transition history and audit metadata are transactional and contain no patient payload.
- Opaque 256-bit bearer tokens are SHA-256 hashed at rest, expire after eight hours, and can be revoked. Passwords use salted BCrypt cost 12. Login attempts are bounded in memory; this single-instance demo limiter needs shared storage before horizontal deployment.
- Requests reject unknown fields/enums, scalar coercion, fractional pressure, excessive size, invalid ranges, duplicate symptoms, future timestamps and non-synthetic identifiers. Prepared SQL and facility scope are mandatory on every object query.
- Clinical/auth responses use no-store. Error bodies never include SQL, stack traces, credentials or submitted assessment values. Do not enable request-body logging.

## Verification limits

Tests use JUnit 5, Mockito and actual local PostgreSQL HTTP integration. Testcontainers clean-cluster verification is explicitly skipped when Docker is inaccessible; local Flyway migration and checksum tests remain real. Dockerfile is supplied but container execution requires a reachable engine. Spring Security 6.5.0 is pinned because compatible newer module artifacts are unavailable in the restricted cache; coordinated dependency upgrade and network-enabled vulnerability scanning are required before any deployment. No production security or clinical-readiness claim is made.
